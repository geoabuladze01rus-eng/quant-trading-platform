# OKX: отдельный пилот исполнения на биржевом демо-счёте

Модуль `paper_trading/okx_demo.py` исполняет ограниченные spot LONG заявки
на биржевом демо-счёте OKX. Он не подключён к автоматическому paper-циклу
и не импортируется публичным API. Локальная paper-бухгалтерия и биржевой
демо-счёт остаются независимыми. Запуск данного модуля сам по себе не создаёт
торгового сигнала и не означает работающего автономного бота.

## Защита пилота

- Для каждого запроса неизменно установлен `x-simulated-trading: 1`.
- Хост фиксирован: `https://openapi.okx.com`, перенаправления запрещены.
  Региональные аккаунты могут требовать другой домен; такой аккаунт пока
  не поддерживается и должен пройти отдельную проверку перед подключением.
- Только BTC-USDT, ETH-USDT, SOL-USDT; cash, buy, FOK; без плеча.
  FOK требует полного исполнения либо отмены. Не заменять на обычный limit
  без отдельного управления защитой частичного исполнения.
- В заявку включены прикреплённые стоп и тейк-профит.
- Максимум 100 USDT на заявку, 1 USDT расчётного риска по стопу,
  не менее 2R после резерва затрат 0,3% от номинала на каждую сторону расчёта.
  Это параметры ограниченного технического пилота, не риск основного счёта.
  Проскальзывание при стопе может увеличить фактический убыток.
- Лимит резервирования 200 USDT за всё время существования журнала.
  Не удаляйте журнал для обхода лимита.
- Проверяются account/instruments: live SPOT, USDT, tickSz, lotSz, minSz,
  комиссии именно этого инструмента (максимум 0,15%) и свободные USDT.
  Расчётный риск дополнительно ограничен 0,5% totalEq демо-счёта.
- Одновременно допускается одна незавершённая позиция. Новые входы блокируются
  до подтверждённой пустой отмены или полного выхода. При суммарном фактическом
  убытке пилота от 2 USDT новые входы запрещены. Бюджет не сбрасывается ежедневно.
- Уникальный signal_id и SQLite BEGIN IMMEDIATE предотвращают повторную
  отправку, в том числе после перезапуска. Тот же ID с новым содержимым запрещён.
- Журнал привязан к хешу UID демо-счёта. Смена ключа на другой счёт блокирует
  исполнение и восстановление; ордера другого счёта не отменяются.
- Таймаут, отказ или некорректное подтверждение оставляют резерв и блокируют
  новые заявки. Повторной автоматической отправки нет. Проверяйте заявку
  через monitor и интерфейс OKX. Блокировка снимается только при восстановлении
  по однозначно совпавшему ордеру и подтверждении завершения позиции.
- Ответ accepted означает принятие заявки, а не исполнение. Для исполнения
  нужен отдельный запрос состояния.
- Срок сигнала проверяется до и после резервирования; expTime ограничивает
  обработку запроса биржей, но НЕ отменяет уже размещённую лимитную заявку.
- monitor отправляет одну отмену просроченного живого входа, затем проверяет
  конечное состояние биржи. Подтверждение запроса отмены не считается отменой.
- При неожиданном частичном исполнении остаток входа отменяется, состояние
  unprotected_partial блокирует новые входы. Автоматической аварийной продажи
  или постановки дополнительного стопа в этом состоянии нет: нужен оператор.
- После полного входа отдельно проверяются ID, инструмент, cash sell, размер,
  цены и состояние прикреплённого защитного algo. Комиссия в базовом активе
  учитывается в остатке позиции. Несовпадение блокирует новые входы.
- Срабатывание algo не означает закрытия: дочерний sell-ордер должен быть
  исполнен полностью. P&L считается по avgPx и фактическим fee/feeCcy. Поддержаны
  комиссии входа в USDT или базовом активе и выхода в USDT; остальные валюты
  комиссии блокируют сверку. Дополнительные rebates в базовом активе пока
  не учитываются как доход и не подтверждают закрытие полного остатка.

## Проверка подключения

Создайте ключ именно в разделе API демо-торговли OKX с Read и Trade,
без Withdrawal. Сохраните три значения в секретных переменных сервиса:

```
OKX_DEMO_API_KEY
OKX_DEMO_API_SECRET
OKX_DEMO_PASSPHRASE
```

Не отправляйте секреты в чат и не сохраняйте в git. На сервере с установленным
пакетом и постоянным диском выполните:

```
python scripts/check_okx_demo.py --journal /app/data/okx-demo.sqlite3
```

Команда только проверяет доступ к балансу. Она не печатает баланс или ключи
и не отправляет ордера. В текущем сервисе Railway демо-ключи отсутствуют.

## Серверный процесс

Мониторинг и восстановление известных заявок каждые 5 секунд:

```
python scripts/run_okx_demo.py --journal /app/data/okx-demo.sqlite3
```

Для однократной проверки добавить --once. Процесс получает файловую блокировку,
не допускающую второй worker для этого журнала. SQLite и lock должны находиться
на одном постоянном диске. Нельзя использовать отдельные журналы для обхода лимитов.

Новые входы по умолчанию выключены. При готовом доверенном источнике сигналов:

```
python scripts/run_okx_demo.py --journal /app/data/okx-demo.sqlite3 --signal-file /app/data/confirmed-signal.json --enable-demo-entries
```

TRADING_MODE должен быть paper, оба LIVE_* gate — false. Источник обновляет
файл атомарной заменой. Файл не должен быть доступен для изменения публичным API
или посторонним пользователям. Все денежные значения — десятичные строки.
Точная схема перечислена в parse_signal в okx_demo_runner.py.

execute_signal допускает только HIGH/VERY HIGH, согласованные старшие таймфреймы,
не менее четырёх различных категорий подтверждения, обязательные trend_4h и
structure_1h, наблюдение не старше 15 секунд, проверку новостей не старше 5 минут
и отсутствие новостной блокировки. Свежесть повторно проверяется перед POST.
Категории: trend_4h, structure_1h, level_retest, volume, liquidity, vwap.

Эти поля являются решением доверенной стратегии. Модуль не пересчитывает
свечи и не подтверждает достоверность проставленных категорий самостоятельно.
Заполнять их без фактического анализа запрещено. submit — низкоуровневый
технический метод; рабочий процесс использует только execute_signal.

Изменения состояния сохраняются в demo_events и выводятся в stdout один раз
при изменении. Это журнал событий, а не подключённые push-уведомления.
Доставка через Telegram/ChatGPT здесь не настроена. Ошибка внешнего обработчика
после записи события не гарантирует доставку; при интеграции нужен отдельный outbox.

## Допуск к автоматическому исполнению ещё не завершён

Перед автономным запуском нужен реально подключённый источник подтверждённых
Crypto Signal Watch сигналов, проверка на демо-бирже полного цикла и доставка
уведомлений. Текущая daily-trend
paper-стратегия не должна автоматически считаться подтверждённым сигналом
по мультитаймфреймовой методике проекта.

Без этого допуска и биржевой проверки пилот не следует развёртывать как
работающего автономного исполнителя. Никакой фактической доходности или
биржевого исполнения тесты с MockTransport не подтверждают.
