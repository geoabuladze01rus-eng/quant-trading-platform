# OKX: отдельный пилот исполнения на биржевом демо-счёте

Модуль `paper_trading/okx_demo.py` исполняет ограниченные spot LONG заявки
на биржевом демо-счёте OKX. Он не подключён к автоматическому paper-циклу
и не импортируется публичным API. Локальная paper-бухгалтерия и биржевой
демо-счёт остаются независимыми. Запуск данного модуля сам по себе не создаёт
торгового сигнала и не означает работающего автономного бота.

## Защита пилота

- Для каждого запроса неизменно установлен `x-simulated-trading: 1`.
- Хост фиксирован: `https://openapi.okx.com`, перенаправления запрещены.
  Региональные аккаунты могут требовать другой домен; такой аккаунт пока
  не поддерживается и должен пройти отдельную проверку перед подключением.
- Только BTC-USDT, ETH-USDT, SOL-USDT; cash, buy, limit; без плеча.
- В заявку включены прикреплённые стоп и тейк-профит.
- Максимум 100 USDT на заявку, 1 USDT расчётного риска по стопу,
  не менее 2R после резерва затрат 0,3% от номинала на каждую сторону расчёта.
  Это параметры ограниченного технического пилота, не риск основного счёта.
  Проскальзывание при стопе может увеличить фактический убыток.
- Лимит резервирования 200 USDT за всё время существования журнала.
  Не удаляйте журнал для обхода лимита.
- Уникальный signal_id и SQLite BEGIN IMMEDIATE предотвращают повторную
  отправку, в том числе после перезапуска. Тот же ID с новым содержимым запрещён.
- Таймаут, отказ или некорректное подтверждение оставляют резерв и блокируют
  новые заявки. Повторной автоматической отправки нет. Проверяйте заявку
  через order_status и интерфейс OKX; автоматическое снятие блокировки не реализовано.
- Ответ accepted означает принятие заявки, а не исполнение. Для исполнения
  нужен отдельный запрос состояния.
- Срок сигнала проверяется до и после резервирования; expTime ограничивает
  обработку запроса биржей, но НЕ отменяет уже размещённую лимитную заявку.

## Проверка подключения

Создайте ключ именно в разделе API демо-торговли OKX с Read и Trade,
без Withdrawal. Сохраните три значения в секретных переменных сервиса:

```
OKX_DEMO_API_KEY
OKX_DEMO_API_SECRET
OKX_DEMO_PASSPHRASE
```

Не отправляйте секреты в чат и не сохраняйте в git. На сервере с установленным
пакетом и постоянным диском выполните:

```
python scripts/check_okx_demo.py --journal /app/data/okx-demo.sqlite3
```

Команда только проверяет доступ к балансу. Она не печатает баланс или ключи
и не отправляет ордера. В текущем сервисе Railway демо-ключи отсутствуют.

## Допуск к автоматическому исполнению ещё не завершён

Нужны проверка торговых правил инструмента (tickSz, lotSz, minSz), баланса,
фактических комиссий, защиты частично исполненного входа, проверки создания
прикреплённого стопа, отмены просроченных лимитных заявок, восстановления
позиции/стопов после рестарта и сверки исполнений с биржей.

Перед автономным запуском нужен мост из подтверждённых Crypto Signal Watch
сигналов с независимыми подтверждениями, фильтром новостей и проверками
свежести, а также мониторинг выхода и уведомления. Текущая daily-trend
paper-стратегия не должна автоматически считаться подтверждённым сигналом
по мультитаймфреймовой методике проекта.

Без этого допуска и биржевой проверки пилот не следует развёртывать как
работающего автономного исполнителя. Никакой фактической доходности или
биржевого исполнения тесты с MockTransport не подтверждают.
